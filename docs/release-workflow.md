# 发布应用更新

先保存[应用配置](configuration.md)。日常发版准备各商店已签名 APK 和一份更新说明，再运行：

```sh
android-release publish demo
```

默认选择应用已配置的全部商店。工具按商店询问 APK 路径；文件名不会决定商店归属。可以为多个商店选择同一个文件，也可以各用一个 APK。

## 提供本次材料

每个 APK 的包名、版本名、版本代码和签名证书须一致，文件内容可以不同。发布包须经过签名、保持完整，并关闭可调试标记。

更新说明全部商店共用，去掉首尾空白后至少 5 个字符。vivo 上限为 200 个字符，其他商店为 500 个字符。文本可以直接粘贴，也可以读取 UTF-8 文件。

```sh
android-release publish demo \
  --apk huawei=/absolute/path/first.apk \
  --apk honor=/absolute/path/second.apk \
  --notes-file /absolute/path/notes.txt
```

未指定的商店在交互中补齐。临时只发部分商店时加 `--channels huawei,honor`。在路径提示输入 `skip` 也能跳过商店，工具会要求明确确认缩小的范围。

## 检查和确认

工具先检查并冻结本次材料，再读取各商店账号权限和应用现状。准备材料和生成提交计划保持离线，商店访问发生在预检阶段。

缺少安装包或安装包检查失败时，先修复材料。预检失败时，可以修复后重查，或明确跳过失败商店。全部选定商店就绪后，会展示应用、版本、各商店 APK、商店应用编号、账号备注、更新说明和发布方式。

核对后输入 `yes`，开始上传和提审。发布方式固定为审核通过后立即上架。单个商店失败后会继续其他商店，结束时列出各商店结果。

只有发布者获准提交这些应用、产物和商店，才能确认。配置账号、生成摘要、运行测试和启动 Web 都不会自动提交。

## 再次进入和继续

```sh
android-release publish demo
```

应用有待处理发布时，先选择继续、查看结果或准备新版本。继续复用已冻结的材料和原更新说明，跳过已受理商店与已确认步骤。

再次提供完全相同的产物、商店范围、配置与更新说明，会回到已有记录。内容或范围变更会建立新的内容记录，最终仍须确认。

请求结果未决时，先查看[状态与恢复](status-and-recovery.md)。所有选定商店已受理表示提交完成。审核和上架继续查询。

## 在浏览器操作

运行 `android-release web` 后，进入应用并发布新版本。按商店选文件、填写说明，然后检查并确认。正式提交前可以返回修改材料，变更后重新检查。已有提交操作时，更换材料会准备另一次发布。

本地草稿保留选定商店、APK 副本和更新说明。耗时操作在本地服务中继续，页面可以离开。回来后先显示已保存进度，再更新商店结果。

重试只处理明确选定的商店，原发布中的其他商店和结果继续保留。提交结果待确认时先检查原请求；商店审核或上架需要人工查看时，进入商店后台并单独记录结果。Web 与 CLI 使用同一套发布记录和请求日志，可以换一个入口继续。
