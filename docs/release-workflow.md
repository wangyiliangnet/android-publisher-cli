# 发布应用更新

先保存[应用配置](configuration.md)。日常发版准备各渠道已签名 APK 和一份更新说明，再运行：

```sh
android-release publish demo
```

默认选择应用已配置的全部渠道。工具逐渠道询问 APK 路径；文件名不会决定渠道归属。可以为多个渠道选择同一个文件，也可以各用一个渠道包。

## 提供本次材料

每个 APK 的包名、版本名、版本代码和签名证书须一致，文件内容可以不同。发布包须经过签名、保持完整，并关闭可调试标记。

更新说明全部渠道共用，去掉首尾空白后至少 5 个字符。vivo 上限为 200 个字符，其他渠道为 500 个字符。文本可以直接粘贴，也可以读取 UTF-8 文件。

```sh
android-release publish demo \
  --apk huawei=/absolute/path/first.apk \
  --apk honor=/absolute/path/second.apk \
  --notes-file /absolute/path/notes.txt
```

未指定的渠道在交互中补齐。临时只发部分渠道时加 `--channels huawei,honor`。在路径提示输入 `skip` 也能跳过渠道，工具会要求明确确认缩小的范围。

## 检查和确认

工具先检查并冻结本次材料，再读取各商店账号权限和应用现状。准备材料和生成提交计划保持离线，商店访问发生在预检阶段。

缺包或本机检查失败时，先修复材料。预检失败时，可以修复后重查，或明确跳过失败渠道。全部选定渠道就绪后，会展示应用、版本、各渠道 APK、商店应用、账号备注、更新说明和发布方式。

核对后输入 `yes`，开始上传和提审。发布方式固定为审核通过后立即上架。单渠道失败后会继续其他渠道，结束时列出各渠道结果。

只有发布者获准提交这些应用、产物和渠道，才能确认。配置账号、生成摘要、运行测试和启动 Web 都不会自动提交。

## 再次进入和继续

```sh
android-release publish demo
```

应用有待处理发布时，先选择继续、查看结果或准备新版本。继续复用已冻结的材料和原更新说明，跳过已受理渠道与已确认步骤。

再次提供完全相同的产物、渠道范围、配置与更新说明，会回到已有记录。内容或范围变更会建立新的内容记录，最终仍须确认。

请求结果未决时，先查看[状态与恢复](status-and-recovery.md)。所有选定渠道已受理表示提交完成。审核和上架继续查询。

## 在浏览器操作

运行 `android-release web` 后，进入应用并选择“准备发布”。逐渠道选文件，填写更新说明，再依次预检和确认。Web 与 CLI 使用同一套发布记录和请求日志，可以换一个入口继续。
