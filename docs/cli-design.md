# CLI 用户故事与交互设计

面向使用终端或本地 Web 的 Android 开发者和发布负责人。日常任务是把一组渠道 APK 提交到应用已配置的全部商店，再跟踪审核和上架结果。

用户故事与业务范围已于 2026-10-29 确认。以下命令和交互作为实现契约。命令、配置和本机状态格式均可按新契约设计，验收以本文的目标行为为准。

## 业务范围

工具在 Apple Silicon Mac 上运行。发布者提供已打包、已签名的 APK，更新华为、荣耀、小米、OPPO、vivo 和应用宝中已有的应用。发布方式固定为审核通过后立即上架。

渠道包是常态。用户明确指定各渠道对应的 APK。文件名和目录名只用于帮助用户选择文件，工具按用户指定的关系处理产物。

首次配置保存长期资料。每次发布提供本次材料。安装 CLI 后，用户即可检查 APK，无需手动安装或配置 Android SDK、JDK 和相关环境变量。

首次创建商店应用、构建签名、定时发布、CI 无人值守和跨平台支持另行设计。

## 用户故事与验收标准

| 用户故事 | 完成标准 |
| --- | --- |
| 首次配置应用 | 引导填写应用名称、包名、渠道账号和商店应用信息，检查访问权限后保存。配置阶段无需 APK。 |
| 准备一次发布 | 选择应用，为各渠道指定 APK，输入或读取一份更新说明。工具校验产物并展示对应关系。 |
| 确认提交范围 | 默认选择全部已配置渠道。材料或预检失败时先停止。用户明确选择跳过后，才缩小提交范围。 |
| 提交应用更新 | 一次连续流程完成准备、检查、核对和提交。确认页覆盖应用、渠道、APK 和更新说明，用户确认一次。 |
| 处理部分失败 | 某渠道提交失败后继续其他渠道。结束时区分已受理、可重试和待核对，并给出下一步。 |
| 继续未完成发布 | 优先找到已有记录，跳过已受理渠道，继续可以安全重试的步骤。已有冻结副本可用时，直接复用原材料。 |
| 查询发布结果 | 按应用查看最近一次发布，也可选择历史记录。分别展示提交、审核、上架和查询是否成功。 |
| 记录人工核对 | 提供后台核对指引，保存对应版本、结果、时间和来源，明确标示人工核对。 |
| 维护渠道凭据 | 首次配置后安全保存在本机，日常复用。失效时引导更新，并提供清除入口。 |

## 命令入口

日常入口是 `publish` 和 `status`。首次配置使用 `app add`。

| 命令 | 用户任务 |
| --- | --- |
| `android-release app add [应用]` | 新建应用配置，逐渠道完成接入。 |
| `android-release app edit [应用]` | 修改长期资料和渠道范围。已有发布记录保留原内容。 |
| `android-release app list` | 查看应用和已配置渠道。 |
| `android-release publish [应用]` | 准备一次更新，或进入已有发布的继续流程。 |
| `android-release status [应用]` | 查询最近一次发布，展示结果和下一步。 |
| `android-release history [应用]` | 查看本机历史发布记录。 |
| `android-release status [应用] --release <记录>` | 查询指定历史发布。 |
| `android-release status [应用] --record-manual` | 引导核对商店后台，并保存人工核对记录。 |
| `android-release account list` | 查看账号备注、凭据可用性和引用该账号的应用。 |
| `android-release account update [渠道] [账号]` | 引导更新凭据，验证后保存。 |
| `android-release account forget [渠道] [账号]` | 展示受影响的应用，清除本机保存的凭据及可复用授权材料。 |
| `android-release doctor` | 检查 CLI 自带组件、私有目录和凭据访问能力，提供修复动作。 |
| `android-release protocols` | 查看各渠道的自动查询与恢复能力。 |
| `android-release version` | 查看版本。 |
| `android-release web [--port 端口] [--no-open]` | 启动 GitHub 风格的本地浏览器工作台。 |

省略应用时，只有一个应用便直接使用；有多个应用时引导选择。所有命令提供独立的 `--help`，先说明任务，再展示最小示例。

`publish` 可接受以下可选参数，减少重复输入：

```sh
android-release publish demo \
  --apk huawei=/tmp/release/one.apk \
  --apk honor=/tmp/release/two.apk \
  --notes-file /tmp/release/notes.txt
```

`--apk` 显式建立渠道与文件的对应关系。未指定的渠道在交互中补齐。用户可用 `--channels huawei,honor` 明确选择本次范围。只有纳入本次范围的渠道需要提供 APK。

参数完整时仍展示提交摘要，并等待终端确认。普通输出以人阅读为主。查询、列表和诊断命令支持 `--json`。JSON 模式遇到缺失凭据时返回可处理的错误及修复入口。

## 首次配置

`app add` 收集应用名称、包名和渠道，再逐渠道配置商店应用标识与账号资料。向导解释字段来自商店后台的哪个位置。

同一个真实渠道账号沿用同一个账号备注。已有账号可直接复用，避免为同一账号创建多份身份。向导读取已有默认值，并保留用户已经完成的配置。

渠道凭据支持终端隐藏输入和本地 Web 表单录入。本机 JSON 和 PEM 路径先检查所有者及 `0600` 权限，再读取；直接粘贴的材料只在当前操作内存中处理。访问检查只读取商店资料，令牌申请与刷新经过账号状态记录。向导保存每个渠道的接入结果，失败时说明需要修复的字段或权限。

## 日常发布流程

```text
选择应用
  → 为各渠道指定 APK
  → 输入更新说明，或读取文本文件
  → 本机校验并冻结本次材料
  → 检查各渠道账号和商店现状
  → 展示提交摘要
  → 确认一次
  → 逐渠道上传和提交
  → 汇总受理结果与下一步
```

更新说明由全部选定渠道共用，每次发布重新提供。输入阶段提前检查各渠道的长度要求。

本机校验检查 APK 的包名、版本、签名、可调试标记和渠道要求。不同渠道的 APK 可以有不同文件内容，包名、版本名、版本代码和签名证书须一致。

缺包或本机校验失败时，停在材料阶段。预检失败时，停在提交确认前。用户可以修复后重查，也可以明确跳过相关渠道。工具展示调整后的完整范围，再请求最终确认。

提交摘要至少包括应用名称和包名、版本名和版本代码、各渠道商店应用、账号备注、APK 对应关系、检查结果、更新说明，以及审核通过后立即上架的发布方式。

发布批次和提交计划由工具建立。用户日常无需命名批次、编写输入 JSON、打开计划文件或复制校验摘要。高级诊断仍可查看记录标识和校验依据。

准备材料和生成提交计划保持离线。提交前冻结 APK，并复核冻结副本。每个业务请求前保存操作意图，取得可验证回执后立即保存。

确认后，单渠道失败继续其他渠道。所有选定渠道均已受理，表示本次提交完成。审核和上架结果由后续查询提供。

## 继续与重复执行

进入 `publish` 时，工具展示该应用尚待处理的发布，提供继续、查看结果和准备新版本的选择。继续时复用原批次的材料、渠道关联和更新说明。

用户重新指定一组 APK 后，工具按各渠道的内容摘要查找已有发布。发现相同产物时先展示已有记录。材料、更新说明和配置快照均一致时，可以直接回到原流程。

更新说明或渠道配置发生变化时，展示差异。用户明确选择新建发布，才建立新的冻结内容。已有批次保持原样。

已受理渠道直接展示结果。已确认完成的步骤直接跳过。确定未执行或已拒绝的步骤按渠道能力处理重试。保留为 `intent` 或 `unknown` 的请求先进入核对流程。

同一渠道、账号和应用存在未决写入时，继续阻止冲突提交。人工核对记录用于补充结果展示；解除未决写入仍须取得能够关联原操作的可验证证据。证据不足时说明阻塞原因和核查路径。

## 查询与人工核对

`status` 默认刷新最近一次发布的远端结果。`history` 列出本机记录，包含版本、时间和渠道摘要，供用户选择。

结果表分别展示提交、审核、上架和查询情况。查询失败时保留上次结果，并标明上次成功查询的时间。每个需要处理的渠道都给出具体动作。

```text
应用：demo    版本：2.4.0（240）

渠道    提交        审核              上架              查询
华为    已受理      审核中            未确认            成功
荣耀    已受理      审核通过          待人工核对        成功
小米    已受理      待人工核对        待人工核对        无自动确认能力
OPPO    可重试      尚未提交          尚未提交          未查询
vivo    已受理      上次：审核中      未确认            本次失败
应用宝  待核对      未确认            未确认            无自动确认能力

下一步：继续 OPPO；核对应用宝提交记录；到后台核对荣耀和小米。
```

`--record-manual` 引导用户选择渠道与本次版本，记录核对结论、核对时间和来源。用户可以引用保存在本机的证据材料，普通输出只显示脱敏摘要。

人工结论标示来源。自动确认和人工核对分别计数。无法关联本次版本的信息作为背景展示，目标结果继续保留为未确认。人工记录可追加修正，原记录留存。

## 凭据与 APK 检查组件

凭据内容以 AES-256-GCM 加密保存在本机私有目录。应用配置保存账号引用，短期令牌和上传授权保存在私有状态。每次保存生成独立密钥，由 macOS 钥匙串保护。密钥通过系统 `security` 的标准输入传递，凭据内容避开进程参数和普通日志。

[Apple Keychain Services](https://developer.apple.com/documentation/security/keychain-services/) 提供加密存储。终端和 Web 输入均经同一套验证后保存，日常自动复用。更新时实际验证新凭据，清除凭据时保留未决请求与操作回执。

APK 检查使用工具管理的 Eclipse Temurin 21.0.13+9 JRE 和官方 apksig 8.13.0。固定下载地址与 SHA256 校验值，安装和修复由工具负责。完整许可证与来源见[第三方声明](../THIRD_PARTY_NOTICES.md)。

独立校验入口使用 [apksig](https://android.googlesource.com/platform/tools/apksig/+/refs/heads/main/README.md) 的公共 API 验证签名，并读取包名、版本代码和可调试标记。版本名支持二进制 Manifest 的直接字符串及资源引用，使用合成 APK 与官方工具对照。安装后离线准备材料直接使用本机组件。

APK 校验组件可用性是发布前置条件。组件故障时给出修复入口。保持完整签名验证，测试造包依赖由贡献者环境承担。

## 输出与退出状态

错误信息说明失败的阶段、受影响渠道、是否已经发出写入请求、是否可以重试，以及具体的下一步命令。输出遵循仓库的敏感信息边界。

| 退出码 | 含义 |
| --- | --- |
| `0` | 本次请求的任务成功；对 `publish` 表示选定渠道全部受理，对查询表示成功取得并展示结果。 |
| `1` | 输入、检查或执行失败。 |
| `2` | 部分渠道已受理，其余渠道发生已确定的失败。 |
| `3` | 提交存在未决请求或冲突阻塞，需要先核对。 |
| `130` | 用户取消或终端中断；输出或下次进入时说明已保存的进度。 |

`publish` 同时存在未决请求和失败时，以 `3` 为准。查询成功返回的审核拒绝、待人工核对或未决提交属于业务结果，通过结果字段表达。

## 实现与验证要求

1. 在独立运行时中验证临时 APK，清空用户 SDK/JDK 环境变量；用临时钥匙串验证凭据读写。实际安装包也应在干净的 Apple Silicon 环境验收。
2. 实现应用和账号向导，检查账号复用、失效更新和清除行为。
3. 实现 `publish` 连续流程，覆盖默认全渠道、显式选包、调整范围和一次确认。
4. 实现继续、查询、历史与人工核对，补齐部分失败和中断恢复体验。
5. 按新契约更新帮助、用户文档和安装包验收。

测试使用合成配置、临时 APK 和模拟商店响应。重点验证签名与元数据错误、确认后材料变化、写入回执丢失、重启继续和跨批次冲突。人工记录须保留来源，也须验证它无法解除缺乏关联证据的未决写入。

渠道真实验证按获准的应用、产物和渠道另行执行。目前六渠道仍以模拟接口验证为主，新交互本身不增加真实协议验证范围。

实现继续遵守[领域词汇表](../GLOSSARY.md)、[架构约束](architecture.md)和[渠道协议依据](channels/protocol-evidence.md)。

## 本地 Web 端

Web 与 CLI 复用应用服务和本机状态，使用相同的配置、选包、预检、确认、提交和查询过程。页面采用 GitHub 风格的浅色导航、表格、边框和状态标签。

Web 仅监听 `127.0.0.1`，请求检查 Host、Origin 与会话令牌。用户逐渠道选择 APK 后，服务流式写入私有临时目录。冻结产物保留在共享记录中，应用图标作为长期资料单独保存。Web 的“账号与凭据”提供接入、更新和清除入口。普通密钥默认隐藏，JSON/PEM 支持私有路径和多行粘贴。验证后保存，接口只返回成功状态；表单在提交、取消和导航时清空。环境页可以直接安装或修复检查组件，并展示版本信息。
