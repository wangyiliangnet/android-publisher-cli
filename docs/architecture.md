# 开发者架构说明

CLI 和本地 Web 共用 `PublisherApplication`。应用配置保存长期资料；发布批次冻结某次更新；渠道目标分别记录请求与结果。术语见[词汇表](../GLOSSARY.md)，用户任务和命令契约见[设计说明](cli-design.md)。

## 代码分工

| 代码 | 职责 |
| --- | --- |
| `src/cli.ts` | 命令、终端问答、人类输出和退出码。 |
| `src/web.ts`、`src/web/` | 本机 HTTP 服务、文件上传和浏览器工作台。 |
| `src/application.ts` | 两端共享的应用、账号、发布、查询和人工核对服务。 |
| `src/setup.ts` | 无需 APK 的长期资料配置。 |
| `src/vault.ts` | 钥匙串密钥、AES-256-GCM 凭据存储和账号引用。 |
| `src/runtime.ts` | 固定版本的检查组件下载、校验、原子安装与调用。 |
| `src/apk-metadata.ts` | 有大小边界的 ZIP、二进制 Manifest 和资源字符串读取。 |
| `tools/ApkVerifierMain.java` | 官方 apksig 的独立入口，验证签名并读取关键身份。 |
| `src/artifact.ts` | 产物冻结、完整性复核和开发用 Android 工具。 |
| `src/engine.ts` | 离线准备、预检、离线计划、提交、查询和核对。 |
| `src/state.ts` | SQLite 请求日志、查询、人工记录、令牌与上传授权。 |
| `src/channels/` | 六个渠道各自的独立协议实现。 |

## 从配置到提交

`app add` 保存包名、渠道应用、账号备注和 API 标识。凭据经终端或受会话保护的 Web 表单输入，私有 JSON/PEM 路径检查所有者与权限。访问检查只读取商店资料，令牌申请和刷新经过账号日志。

`publish` 默认选择应用的全部已配置渠道。只为本次明确选择的渠道提供 APK。`previewBatch` 检查材料，`prepare` 复制并冻结 APK、更新说明和小米图标，整个阶段离线。

`preflight` 读取账号和应用现状，结果绑定到批次。已有写入步骤的渠道保留原预检，已受理渠道直接跳过。`review` 离线建立具体渠道范围的提交计划，应用服务将文件保存在本机私有目录。

终端或浏览器展示摘要，并在用户明确确认后调用提交。计划绑定应用、账号、渠道、产物摘要、版本、签名、说明、预检与发布方式。`submit` 在首个业务请求前重新验证计划和所有待执行产物。

每个业务步骤先保存 `intent`，再发出请求。取得可验证回执后立即保存 `confirmed_applied`。丢失响应或无法验证回执时保留 `intent` 或 `unknown`。同一渠道、账号和应用的未决请求阻止其他批次的冲突写入。

应用服务在提交前保存确认的渠道范围。已有执行记录的渠道须保留，提交时再次检查这一点，防止旧计划隐藏已执行或未决的渠道。状态汇总按生效范围展示。

## 继续和查询

相同产物、配置、说明和生效范围复用已有记录。内容或范围变更建立新内容记录。已有批次保持不可变。继续时复用冻结材料和回执，跳过已受理渠道与已确认步骤。

执行、审核、上架和查询健康分别保存。只有本机已有受理回执，且远端证据关联本次版本，才能更新自动审核和上架状态。背景信息放在 `channel_context`。

人工核对写入独立的 `manual_observations`，记录版本、批次摘要、产物摘要、来源、观察时间和记录时间。人工记录不修改自动结果、操作回执或冲突锁。

`reconcile` 只读取能证明原请求的远端证据。当前六渠道尚无足够依据自动解除丢失响应的写入，需要保留阻塞并进一步核查。

## 凭据与本机组件

本机资料位于 `~/Library/Application Support/AndroidPublisherCLI/v2/`。文件限制为当前用户访问。SQLite 使用 WAL 和完全同步设置。

凭据内容以 AES-256-GCM 加密，AAD 绑定渠道与账号。每次保存创建新的随机密钥，密钥保存在 macOS 钥匙串。`security` 接收短密钥的标准输入，密钥和凭据内容都避开进程参数。验证新凭据前清除可复用令牌，保持未决申请的阻塞。

账号清除删除凭据与可复用材料，保留操作回执和未决令牌记录。不同账号的授权材料分别处理。

检查组件采用固定下载 URL 和 SHA256。安装到私有暂存目录，校验归档、Java 启动和校验器后原子替换。发布使用独立运行时，不读取用户 SDK 或 JDK 设置。`AndroidTools` 保留用于生成和对照验证合成 APK。

## 本地 Web 边界

Web 仅监听 IPv4 回环地址。页面和静态资源本机提供，使用 CSP、Host/Origin 校验和随机会话令牌。共享业务变更串行执行；读取已保存状态、草稿和任务轮询无需等待长操作。`accounts.update` 接受按渠道限定的文本或私有文件路径，经共享的账号验证后写入凭据库。凭据更新响应固定为 `{updated:true}`，格式错误使用固定错误代码，任意后端异常保持脱敏。

页面的凭据表单只在 DOM 和当前请求局部变量中保留输入。提交、关闭、取消或导航时清空；服务器清空请求引用与原始缓冲区。原始材料留在内存，本机路径按终端规则读取。`doctor.repair` 在相同私有目录安装检查组件，诊断包含版本与运行信息。

`web/workspace.ts` 只允许保存应用和发布表单字段。草稿不包含凭据或提交授权。APK 上传副本保存在私有目录，服务重启后仍能恢复材料。文件流使用随机目录、独占写入和大小限制，图标独立长期保存。

`web/jobs.ts` 接收明确动作和请求标识，重复请求复用同一操作。任务在浏览器断开后继续，结果保留到本地服务关闭。任务列表不包含密钥输入。服务重启后的业务恢复仍以 SQLite 日志和回执为准，不自动重发提交。

对已有业务操作的记录，显式 `attempt_only` 计划只授权本次尝试渠道，并另行绑定原发布范围。提交时校验该范围保持一致，原记录不缩小；默认提交计划仍保留已有操作渠道的范围保护。

应用名称与稳定短名分别保存。渠道就绪记录绑定包名、商店应用和账号配置；资料变更后需要重新验证。凭据验证成功后更新引用应用的接入状态。HTTP 返回的渠道错误和查询错误使用固定脱敏提示。

账号列表同时保留当前配置、未完成发布和历史记录需要的账号。`account-profiles/` 只保存渠道、账号备注与公开 API 标识，供移除渠道后复用或清除本机密钥。清除密钥仍保留身份，已知 API 标识沿用同一账号，防止通过改备注绕过未决授权。历史发布修复使用原配置绑定，不改变当前应用的接入状态，也不解除未决请求。

## 验证

`npm run check` 执行类型检查、构建和全部测试。测试覆盖完整发布、中断、重复执行、旧计划范围、人工记录隔离、凭据加密、本地 Web 请求防护与上传。

真实 APK 测试临时生成签名包，对照 Android 官方工具与独立校验入口。设置 `PUBLISHER_REQUIRE_ANDROID_TESTS=1` 强制执行；也可通过 `PUBLISHER_MANAGED_TEST_ROOT` 指向已安装检查组件的隔离目录，验证完整管理运行时。

渠道测试使用模拟响应，不代表真实账号权限与公开上架验证。协议依据见[渠道文档](channels/protocol-evidence.md)。
