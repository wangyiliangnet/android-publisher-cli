# 开发者架构说明

CLI 和本地 Web 共用 `PublisherApplication`。应用配置保存长期资料；发布批次冻结某次更新；发布目标分别记录请求与结果。术语见[词汇表](../GLOSSARY.md)，用户任务和命令契约见[设计说明](cli-design.md)。

## 文案与数据映射

用户界面使用“应用、商店、账号、凭据”。`Channel`、`ProjectChannel`、`channel`、`channels` 和 CLI 的 `app channels`、`--channels` 保留原名，分别承载商店标识、应用在商店的配置和所选范围。一个应用在每个商店最多有一份配置；账号可跨应用复用，凭据随账号保存，各应用的访问检查分别记录。

| `src/apk-metadata.ts` | 有大小边界的 ZIP、二进制 Manifest 和资源字符串读取。 |

| `src/channels/` | 六个商店各自的独立协议实现。 |

## 从配置到提交

`app add` 只保存应用名称和包名，应用允许没有商店。`app channels` 保存当前应用的商店配置，包括应用编号、账号引用和商店所需资料。`account add` 可在没有应用时独立保存账号资料和凭据。凭据经终端或受会话保护的 Web 表单输入，私有 JSON/PEM 路径检查所有者与权限。访问检查只读取商店资料，令牌申请和刷新经过账号日志。

`publish` 默认选择应用的全部已配置商店。只为本次明确选择的商店提供 APK。`previewBatch` 检查材料，`prepare` 复制并冻结 APK、更新说明和小米图标，整个阶段离线。

`preflight` 读取账号和应用现状，结果绑定到批次。已有写入步骤的商店保留原预检，已受理商店直接跳过。`review` 离线建立具体商店范围的提交计划，应用服务将文件保存在本地私有目录。

终端或浏览器展示摘要，并在用户明确确认后调用提交。计划绑定应用、账号、商店、产物摘要、版本、签名、说明、预检与发布方式。`submit` 在首个业务请求前重新验证计划和所有待执行产物。

每个业务步骤先保存 `intent`，再发出请求。取得可验证回执后立即保存 `confirmed_applied`。丢失响应或无法验证回执时保留 `intent` 或 `unknown`。同一商店、账号和应用的未决请求阻止其他批次的冲突写入。

应用服务在提交前保存确认的商店范围。已有执行记录的商店须保留，提交时再次检查这一点，防止旧计划隐藏已执行或未决的商店。状态汇总按生效范围展示。

## 继续和查询

相同产物、配置、说明和生效范围复用已有记录。内容或范围变更建立新内容记录。已有批次保持不可变。继续时复用冻结材料和回执，跳过已受理商店与已确认步骤。

执行、审核、上架和查询健康分别保存。只有本地已有受理回执，且远端证据关联本次版本，才能更新自动审核和上架状态。背景信息放在 `channel_context`。

人工核对写入独立的 `manual_observations`，记录版本、批次摘要、产物摘要、来源、观察时间和记录时间。人工记录不修改自动结果、操作回执或冲突锁。

`reconcile` 只读取能证明原请求的远端证据。当前六个商店尚无足够依据自动解除丢失响应的写入，需要保留阻塞并进一步核查。

## 凭据与本地组件

本地资料位于 `~/Library/Application Support/AndroidPublisherCLI/v2/`。文件限制为当前用户访问。SQLite 使用 WAL 和完全同步设置。

凭据内容以 AES-256-GCM 加密，AAD 绑定商店与账号。每次保存创建新的随机密钥，密钥保存在 macOS 钥匙串。`security` 接收短密钥的标准输入，密钥和凭据内容都避开进程参数。验证新凭据前清除可复用令牌，保持未决申请的阻塞。

清除凭据删除密钥与可复用材料，保留操作回执和未决令牌记录。不同账号的授权材料分别处理。

检查组件采用固定下载 URL 和 SHA256。安装到私有暂存目录，校验归档、Java 启动和校验器后原子替换。发布使用独立运行时，不读取用户 SDK 或 JDK 设置。`AndroidTools` 保留用于生成和对照验证合成 APK。

## 本地 Web 边界

Web 仅监听 IPv4 回环地址。页面和静态资源均由本地服务提供，使用 CSP、Host/Origin 校验和随机会话令牌。共享业务变更串行执行；读取已保存状态、草稿和任务轮询无需等待长操作。`accounts.update` 接受按商店限定的文本或私有文件路径，经共享的账号验证后写入凭据库。凭据更新响应固定为 `{updated:true}`，格式错误使用固定错误代码，任意后端异常保持脱敏。

页面的凭据表单只在 DOM 和当前请求局部变量中保留输入。提交、关闭、取消或导航时清空；服务器清空请求引用与原始缓冲区。原始材料留在内存，本地路径按终端规则读取。`doctor.repair` 在相同私有目录安装检查组件，诊断包含版本与运行信息。

`web/workspace.ts` 只允许保存应用和发布表单字段。应用基本资料草稿与商店配置草稿分别保存，编辑名称不会覆盖未完成的商店资料。草稿不包含凭据或提交授权。发布草稿只在所选商店已有 APK 或更新说明含非空白字符时保存，空内容清除对应草稿。读取时同样清理旧版空草稿，已有发布批次和材料检查记录保持不变。APK 上传副本保存在私有目录，服务重启后仍能恢复材料。文件流使用随机目录、独占写入和大小限制，图标独立长期保存。

`web/jobs.ts` 接收明确动作和请求标识，重复请求复用同一操作。任务在浏览器断开后继续，结果保留到本地服务关闭。任务列表不包含密钥输入。服务重启后的业务恢复仍以 SQLite 日志和回执为准，不自动重发提交。

对已有业务操作的记录，显式 `attempt_only` 计划只授权本次尝试商店，并另行绑定原发布范围。提交时校验该范围保持一致，原记录不缩小；默认提交计划仍保留已有操作商店的范围保护。

应用名称与稳定短名分别保存。商店就绪记录绑定包名、商店应用编号和账号配置；资料变更后需要重新验证。账号没有关联应用时，只检查凭据格式并加密保存，尚不确认应用访问权限。有关联应用时逐一验证，至少一个应用通过才替换凭据；各应用分别记录验证结果，全部失败时保留旧凭据。HTTP 返回的商店错误和查询错误使用固定脱敏提示。

账号列表归集当前配置、未完成发布和历史记录需要的账号，显式移除的账号除外。`account-profiles/` 独立保存商店、账号备注与公开 API 标识。新建账号和移除最后一个关联商店后，仍可复用账号或更新、清除本地密钥。清除密钥仍保留身份，已知 API 标识沿用同一账号，防止通过改备注绕过未决授权。历史发布修复使用原配置绑定，不改变当前应用的接入状态，也不解除未决请求。

账号移除通过 `account remove` 和 `accounts.remove` 共用校验：账号须不再被任何应用选用；正在执行的提交、未决业务请求和未决令牌申请均阻止移除。SQLite 的 `running_submissions` 表记录执行批次、商店范围和进程。CLI 与 Web 用它检查提交是否仍在运行，覆盖首个业务意图保存前的工具准备阶段。执行结束后清除本次记录；进程退出后，未决保护仍以业务和令牌日志为准。没有写入的材料检查记录不阻止移除。

`accounts.list` 的 `apps` 保留历史凭据修复需要的应用，`removal` 单列当前选用关系和移除条件。Web 的关联应用列使用当前选用关系。

移除先清除凭据与可复用材料，再在 SQLite 的 `removed_accounts` 表保存移除标记。账号列表过滤这些标记，历史批次和回执不变。`account-profiles/` 继续保留公开身份约束，避免更换备注或 API 标识制造另一份身份。显式保存同一账号或重新为应用选用该账号时清除标记，需要重新填写凭据。

## 验证

`npm run check` 执行类型检查、构建和全部测试。测试覆盖完整发布、中断、重复执行、旧计划范围、人工记录隔离、凭据加密、本地 Web 请求防护与上传。

真实 APK 测试临时生成签名包，对照 Android 官方工具与独立校验入口。设置 `PUBLISHER_REQUIRE_ANDROID_TESTS=1` 强制执行；也可通过 `PUBLISHER_MANAGED_TEST_ROOT` 指向已安装检查组件的隔离目录，验证完整管理运行时。

商店测试使用模拟响应，不代表真实账号权限与公开上架验证。协议依据见[商店文档](channels/protocol-evidence.md)。
