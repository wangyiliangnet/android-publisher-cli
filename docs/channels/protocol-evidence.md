# 渠道协议能力与验证依据

修改渠道适配器前，先按本页确认接口能力和验证限制。操作者读取查询结果的方法见[状态解释](automatic-observation.md)。

也可以在本机查看离线能力目录：

```sh
release protocols
```

公开仓库只保存测试及合成测试数据，不保存真实账号证据。查看验证结果时，区分以下状态：

| 标记 | 说明 |
| --- | --- |
| `protocol_mock_verified` | 已通过对应协议的合成测试 |
| `account_verified` | 账号验证状态，不能由合成测试推导 |
| `live_verified` | 真实环境验证状态，不能由合成测试推导 |

## 已实现范围

目前支持已有应用的版本更新。生产提交使用 `after_approval`，即渠道审核通过后立即发布。通用首次上架和任意元数据管理不在当前范围内。执行前，检查当前应用的准确预检结果及已批准计划。

| 渠道 | 已实现的更新步骤 | 修改实现时要保留的限制 |
| --- | --- | --- |
| 华为应用市场 | 申请上传授权、上传 APK、绑定、更新允许的元数据、提审 | 包处理为异步；上传来源必须符合受控主机策略；没有通用的响应丢失重试依据 |
| 荣耀 | 申请上传授权、上传 APK、绑定、更新允许的元数据、提审 | 使用账号级 API 凭据；查询特定版本审核证据需要发布标识；文档未说明的清理或重试行为保持阻塞 |
| 小米 | 签名查询包信息并推送 | 需要图标和公钥证书，并按适用条件提供结构化测试账号数据；审核仅能推测，API 无法核实审核或上架结果 |
| OPPO | 申请上传授权、上传 APK、提审 | 上传授权一次性使用，需匹配准确的批准意图和预检；有效期不明或响应丢失时不能盲目重试 |
| vivo | 上传 APK、提审 | 仅支持单 APK 更新，32/64 位双包编排暂缓；有歧义的协议选择需要账号验证依据 |
| 应用宝 | 申请上传授权、上传 APK、提审 | 使用主开发者账号；未绑定版本的审核信息不能证明本次目标状态；公开页版本只作独立参考 |

测试覆盖合成成功和错误响应、大整数标识、格式错误或缺失字段、上传授权限制、账号协调、持久化回执，以及结果不确定的写入。这些测试不证明真实访问权限、审核时间、公开上架、版权合规或当前服务权限。

### 修改适配器时如何记录依据

在 PR 中列明所用的官方接口文档和字段。说明来源是否可访问，以及哪些行为仍待账号核验。补充对应的合成成功和错误用例。

遇到缺失字段、无法识别的结果或旧版本证据时，保持未知状态，不据此确认目标成功。

## 应用宝公开页面请求约束

公开页面查询使用 HTTPS，不携带凭据、Cookie 或浏览器会话。查询请求必须符合主机、包路径、时限和响应大小限制。禁止重定向。

只有页面结构化数据与所请求的包匹配时，才能读取版本。若结构不符，按查询失败处理。不能从附近文本猜取版本号。
