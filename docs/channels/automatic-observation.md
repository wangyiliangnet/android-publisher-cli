# 自动查询说明

查看发布进度时，先运行：

```sh
release batch status --batch BATCH_ID --refresh
```

把 `BATCH_ID` 换成你的批次名。命令会查询整个批次，不需要先登录浏览器或手工录入状态。具体操作见[日常发布](../daily-cli-workflow.md#查询与报告)。

读表格时，按下面的顺序检查：

| 看哪里 | 能回答什么 | 如何判断 |
| --- | --- | --- |
| 执行 | 商店是否受理了提交 | “已受理”只说明提交被接收 |
| 审核 | 本次目标版本是否通过审核 | 与执行状态分开看；“未知”表示尚无足够证据 |
| 上架 | 本次目标版本是否已公开上架 | 审核通过不能直接代替上架结果 |
| 查询、最近成功查询 | 这次查询是否成功，数据有多新 | 结合来源健康状态和采集时间判断 |

JSON 中的 `execution_phase` 为 `submitted` 时，同样只表示已受理。推测、当前渠道信息和无法关联到本次版本的信息保存在 `channel_context` 中，并附标签与采集时间。这些信息可供参考，不会增加已核实的审核通过或上架数量，也不能解除结果未知的写入阻塞。

## 小米

### 看到“审核通过（推测）”时

先确认这是推测，再看目标版本的审核和上架状态。小米查询接口返回该账号下的版本名和版本号。官方将该接口定义为包查询，没有说明返回值是与版本绑定的审核或公开上架结果。接口依据见[官方 API 指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1134)。

只有本地已保存与本次提交匹配的受理回执，工具才会用版本号比较生成推测：

| API 返回的版本号 | 显示的推测 | 你能据此知道什么 |
| --- | --- | --- |
| 低于冻结目标 | 审核中（推测） | 查询到的版本尚未达到本次已提交目标 |
| 等于冻结目标 | 审核通过（推测） | API 已返回目标版本，审核和公开上架仍未核实 |
| 高于冻结目标 | 未知 | 查询结果可能属于后续版本 |
| 没有已确认的本地提交 | 未知 | 不能用版本比较确认是否已提交或处于何种审核状态 |

输出会保留推测依据，并标记 `association: unconfirmed`。查询失败时不会生成新推测。API 无法证明目标状态时，`review_state` 和 `availability_state` 仍为未知。需要确认具体结果时，到渠道后台核实。不要用推测恢复被阻塞的提交。

## 应用宝

### 看到“未确认属于本次版本”时

把这条信息作为当前渠道参考，继续检查它是否能对应本次提交。工具会分别查询：

- 开发者审核接口中的当前审核信息，包括审核中、驳回、通过和撤回。未知状态码保留为未知；驳回说明会限制长度并脱敏。
- 该包官方公开详情页显示的商店版本。

这些结果都标注“未确认属于本次版本”。没有版本标识的审核信息，可能来自另一次提交。公开商店版本也不会自动把审核结果绑定到本次固定保存的版本。即使版本文本一致，也不足以确认目标审核或上架状态，不能解除写入阻塞。

接口依据见[应用宝开发者指南](https://wiki.open.qq.com/index.html#/guide/develop?id=4015262492)，公开版本来源为[应用宝商店](https://sj.qq.com/)。自动来源无法回答具体的版本关联问题时，再到后台核实。

## 部分失败与缓存

### 看到“部分来源失败”或“缓存”时

先看失败的是哪个来源，再看保留数据的采集时间。API 和公开商店页面的健康状态分别记录。API 失败时，公开版本可能仍能查到。页面失败时，审核信息也可能仍有用。公开查询成功不能代替 API 鉴权成功。

| 情况 | 结果的含义 | 下一步 |
| --- | --- | --- |
| 一部分来源失败 | 其他来源可能仍有可用信息 | 按失败来源的提示处理账号、协议或页面问题 |
| 显示缓存及旧采集时间 | 这是以前保存的事实 | 不把它当成本次新查询的结果 |
| 只有推测或未关联信息 | 还不能确认本次目标状态 | 具体问题仍无法确认时，到渠道后台核实 |
| 已核实证据有争议 | 参考信息没有解决证据冲突 | 保留争议，继续调查对应操作 |

后续查询失败不会删除有用缓存，也不会更新缓存事实的原始采集时间。报告同样区分缓存事实与当前查询结果。阅读报告时，同时查看状态、来源和时间。
