# 维护者：版本发布

面向创建 CLI 标签、草稿和公开版本的维护者。开始前，按[贡献指南](https://github.com/wangyiliangnet/android-publisher-cli/blob/main/CONTRIBUTING.md)完成 PR、审查和必需 CI；签名包的制作见[构建与分发](mac-cli-delivery.md)。本流程不向 Android 商店提审。

## 版本规则

使用不带 `v` 前缀的 SemVer 风格版本作为工作流输入，标签为 `vVERSION`。开发构建在可用时报告开发版本和提交。不得替换已发布标签，或用同一安装包版本承载不同字节。

发布前通过 PR 更新 [CHANGELOG.md](../CHANGELOG.md)，说明用户可见变化、迁移要求、已知限制及分发签名状态。测试版也需说明状态兼容性。

## 创建并复核草稿

1. 确认发布说明和修复已通过正常 PR 合入 `main`，该准确提交的必需 CI **`check`** 已通过。
2. 在 GitHub Actions 中对当前 `main` 手工运行发布工作流，输入版本，例如 `0.1.0-beta.1`。
3. 工作流验证版本与当前 main，重新执行完整检查，构建 ad-hoc 签名的 arm64 CI 预览，并完成双版本安装、升级、回滚、卸载、篡改和符号链接拒绝验收。成功后才创建轻量标签与 GitHub 发布草稿。
4. 下载草稿的实际产物，核对标签与提交、安装包元数据、校验和、签名与架构、许可证及声明、安装结果和说明。检查允许清单，确认没有账号文件、密钥、应用 APK、运行状态、原始响应或私有文档。
5. 确认说明明确标注 **CI 预览、ad-hoc 签名、未公证、没有稳定的钥匙串信任身份**，测试版标为预发布。
6. 最终审阅后手工公开发布。工作流只创建草稿，不会自动公开发布。

[发布工作流](https://github.com/wangyiliangnet/android-publisher-cli/blob/main/.github/workflows/release.yml)是任务与权限的配置来源。只有草稿任务获得创建标签和草稿所需的写权限，且不检出源码。常规检查不上传发布产物；草稿任务使用同次运行的不可变产物。正式签名与 Apple 公证另行配置，预览检查通过不代表已完成这些步骤。

## 创建或上传中断

当 `main` 仍指向已测试提交时，在原运行中使用 **Re-run failed jobs（重新运行失败任务）**，保留该次产物字节。重新触发或构建可能产生不同字节，不能用来替换已有匹配草稿。

工作流先核对轻量标签、草稿元数据和预期摘要，再下载已有资产验证字节，只上传缺失文件。已公开版本、标签目标不同、元数据或字节冲突、额外资产均会被拒绝；不会替换标签或已有资产。若 main 已变化或冲突仍在，先调查，再按正常流程准备新版本。

候选验收失败时通过 PR 修复，再构建新候选。公开发布后提供新版本，不修改已有产物。工具回滚只切换本机程序，不撤销商店写入或绕过本地状态结构检查。
