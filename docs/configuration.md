# 配置应用与商店账号

应用配置告诉工具：这个应用要发布到哪些商店，各商店用哪个账号、对应哪个应用。配置保存后，每次发版只需提供新的 APK 和更新说明。

应用以 Android 包名识别，商店是发布平台。每个商店分别保存该应用的编号、选用账号和所需资料。账号可以由多个应用共用，凭据随账号管理。

先在各商店后台创建好应用，并取得更新应用的 API 权限。CLI 只提交已有应用的版本更新。

## 创建应用配置

```sh
android-release app add demo
```

`demo` 是供命令行选择应用的稳定短名，例如 `reader`，与商店名称、App ID 和包名分别使用。短名使用字母、数字、点、横线和下划线，以字母或数字开头，最多 128 个字符。Web 可以填写中文应用名称，并自动生成短名；两端显示同一个应用名称。

在 Web 中，选择“添加应用”，填写名称和 Android 包名，点击“创建应用”即可保存。CLI 同样先询问名称和包名。应用可以暂不配置商店，首次创建无需 APK 或商店账号。

## 为应用配置商店

Web 中进入应用，选择“应用设置 → 发布商店”，再点击“添加商店”。应用详情页只显示商店名称摘要，“管理”可直接打开此设置页。尚未配置商店时，也可点击“配置商店”开始添加。

先选择商店，再核对当前应用的商店应用编号或包名，选择已有账号或快捷新增账号，最后验证应用访问权限。页面始终显示当前应用的名称和包名。未完成的商店资料保存在本地草稿中。

修改已有配置时，在“发布商店”中选择对应商店的“编辑配置”。这里只设置当前应用的商店资料和选用账号；共享账号与凭据通过全局“商店账号”入口管理。

CLI 使用独立命令配置商店：

```sh
android-release app channels demo
```

向导列出已有账号供复用。首次选择商店不会默认全选，只选华为时输入 `huawei`，选择多个时输入 `huawei,honor`。修改时，以已有商店作为默认值；输入 `none` 可移除全部商店。应用和已有发布记录继续保留。

可用商店如下：

| 商店 | 命令和配置中的名称 |
| --- | --- |
| 华为 | `huawei` |
| 荣耀 | `honor` |
| 小米 | `xiaomi` |
| OPPO | `oppo` |
| vivo | `vivo` |
| 应用宝 | `tencent` |

应用包名来自已保存的应用资料，例如 `com.example.app`。所有 APK 须与此一致。配置商店只关联商店中已有的应用，保存应用资料不会修改商店内容。

## 按商店准备资料

只需准备你选中的商店。App ID 是商店给应用分配的编号，各商店可能不同；API 接入标识用于确定发起请求的账号或客户端。凭据用于证明你有权使用该账号，在接入商店时再输入。

“账号备注”由你给本地保存的账号取名。每个商店只有一个账号时，直接回车使用默认值，如 `huawei-main`。同一个账号请始终使用同一备注；CLI 用它归集访问令牌和未完成操作，随意改名会拆散这些记录。OPPO 也单独保存账号备注和 `client_id`。

### 华为

在 [AppGallery Connect](https://developer.huawei.com/consumer/en/doc/AppGallery-connect-Guides/agcapi-overview-0000001158245083) 准备应用资料和服务账号。

- 向导中的 **App ID**：从该应用后台复制的应用编号。
- 连接时的 **服务账号 JSON 文件**：包含服务账号及私钥的文件。当前实现需要 `key_id`、`sub_account` 和 `private_key`。终端输入文件绝对路径；Web 可输入同样的私有路径，或粘贴完整 JSON 内容。工具用它为请求签名。

更新说明会写入后台已有的简体中文条目，预检时自动查找，无需填写“中文语言 ID”。若提示中文条目缺失或不唯一，先在后台核对语言配置，再重新预检。

### 荣耀

在[荣耀开发者平台](https://developer.honor.com/cn/doc/guides/101359) 准备应用编号和 API 客户端资料。

- 向导中的 **App ID**：该应用的商店编号。
- 向导中的 **client_id**：API 客户端 ID。
- 连接时的 **client_secret**：与该 `client_id` 配对的密钥。

更新说明同样自动选择后台已有的简体中文条目。`App ID` 标识应用，`client_id` 标识 API 客户端，两者分别填写。

### 小米

按[小米自动发布 API 指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1134) 准备发布资料。

- 向导中的 **userName**：自动发布 API 使用的开发者账号。
- **图标文件路径**：应用图标在本地的绝对路径。小米 API 提交更新时同时需要图标。
- **隐私政策地址**：应用隐私政策的 HTTPS 网页地址，不带查询参数或 `#` 片段。
- 连接时的 **api_secret**：API 密钥。
- 连接时的 **public_key_pem 文件**：API 使用的 RSA 公钥或证书，以 PEM 文本保存，供 CLI 生成请求签名材料。
- 可选的 **test_account_json 文件**：供审核人员登录应用的测试账号资料；不需要提供时直接回车。文件结构按官方 API 的测试账号字段准备。

应用标识直接使用前面填写的包名，无需再找一份商店 App ID。

### OPPO

在 [OPPO 开发者后台](https://open.oppomobile.com/) 准备 API 接入资料。

向导分别填写账号备注和 **client_id**，连接时输入与客户端配对的 **client_secret**。应用标识使用包名。CLI 会读取商店中已有的应用资料，再提交版本更新。

### vivo

按 [vivo API 接入指南](https://developer.vivo.com/doc/detail?id=73) 取得账号的 API 接入资料。

向导填写 **access_key**，连接时输入与它配对的 **access_secret**。应用标识使用包名。当前实现每个批次向 vivo 提交一个 APK。

### 应用宝

按[应用宝开发者 API 指南](https://wiki.open.qq.com/index.html#/guide/develop?id=4015262492) 准备主开发者账号资料。

- 向导中的 **App ID**：该应用的 AppID。
- 向导中的 **uid**：主开发者账号的用户 ID。
- 连接时的 **api_secret**：该账号的 API 密钥。

AppID 和 uid 分别标识应用与账号，不能互换。

## 保存和修改

向导最后会按商店列出应用编号或包名、账号备注和 API 接入标识。核对后输入 `yes` 保存；随时输入 `cancel` 取消。保存后继续在终端接入凭据，并只读检查各商店访问权限。接入失败的商店会给出修复命令，已填写资料仍保留。

修改应用名称和包名时运行：

```sh
android-release app edit demo
```

修改商店配置继续使用 `app channels demo`。商店向导会用已有值作为默认值，包括账号备注，并保留旧配置中手动指定的更新说明语言。更改只影响以后创建的发布批次，已保存批次继续使用创建时的配置。若要改用另一个真实账号，也应更换账号备注。

## 独立管理商店账号

商店账号可以在没有应用时独立创建。Web 中打开“商店账号”，选择“添加账号”，按商店填写账号备注和 API 接入标识，再接入凭据。CLI 使用：

```sh
android-release account add honor honor-main
```

同一个账号可由多个应用选择。每个应用分别保存自己的商店中的应用资料和访问验证结果。账号能访问应用 A，不代表它也能访问应用 B。

## 移除不再使用的账号

Web 中打开“商店账号”，点击对应账号的“移除账号”，核对商店和账号备注后确认。CLI 使用：

```sh
android-release account remove honor honor-main
```

仍被应用选用的账号需要先解除关联。到“应用设置 → 发布商店”更换账号，或移除对应商店配置，再返回账号页操作。正在执行的提交、未决业务请求或未决令牌申请也会阻止移除，需要先处理原记录。尚未开始提交的材料检查记录不会单独阻止移除。

移除会清除本地凭据、可复用令牌和上传授权，并从账号列表隐藏此账号。历史发布的账号身份、材料和操作回执继续保留，商店中的真实账号不受影响。历史记录不会使账号重新出现在列表中。

重新使用时，沿用原账号备注和 API 接入标识添加，再填写凭据。只想暂时清除密钥时，使用“清除本地凭据”或 `account forget`，账号仍保留。

## 凭据

Web 中打开“商店账号”，选择相应账号的“填写凭据”或“更新凭据”。普通密钥使用密码输入框。JSON 和 PEM 材料可以填写本地私有文件路径，也可以直接粘贴完整内容。材料默认遮蔽，可临时显示核对；PEM 的换行会保留。

未关联应用时，点击“保存凭据”，工具检查材料格式并加密保存，提示“尚未验证应用访问”。已有关联应用时，点击“验证并保存”，工具分别只读验证各应用；至少一个应用验证通过后保存，并分别记录访问结果。全部验证失败时保留已有凭据。提交、取消、关闭或离开表单时会清空输入，页面不将凭据写入浏览器存储，接口与列表只返回接入状态。

终端也可运行 `android-release account update 商店 账号备注`，通过隐藏输入和私有文件路径接入。两种入口共用验证、存储和令牌记录。

通过本地文件路径读取的华为服务账号 JSON、小米公钥或证书、可选测试账号 JSON 须属于当前用户，权限为 `0600`。文件路径方式使用相同的权限检查：

```sh
chmod 600 "/absolute/path/service-account.json"
chmod 600 "/absolute/path/xiaomi-public-key.pem"
```

按所用商店选择相应文件。使用真实绝对路径，文件及其父目录不能经过符号链接。Web 的材料路径也使用同样规则，`~` 不会自动展开。直接粘贴的内容仅在本次操作内存中处理，原始材料不会写入上传目录。

凭据使用 AES-256-GCM 加密后保存在本地私有目录，加密密钥保存在 macOS 钥匙串。已关联应用的账号更新凭据时先验证，保存成功后替换旧材料。清除使用 `android-release account forget 商店 账号备注`。短期令牌和上传授权保存在本地私有状态；操作回执和未决请求记录继续保留。

Web 的“清除本地凭据”清除本工具保存的凭据和可复用授权材料，商店账号资料仍保留。再次发布前需要重新填写凭据；商店中的账号、应用和授权不受此操作影响。

密钥材料保存在仓库外，不要放进 issue、普通日志或发布附件。

配置保存后，继续[发布应用更新](release-workflow.md)。
